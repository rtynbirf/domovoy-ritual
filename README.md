**Формула:** A = ПОРАБОТАЛ · СДЕЛАЛ · УБРАЛ ЗА СОБОЙ · ЗАКРЫЛ · ВЫШЕЛ ЧИСТЫМ

Дом — это аккаунт, репозиторий, чат, кухня: любое место, где ведётся работа. Закон один для всех мест, потому что состояние дома — это состояние, а состояния подчиняются теории конечных автоматов.

---

## I. Ритуал дома (словесная формула)

1. **ВОШЁЛ** — вошёл в дом: огляделся, что не закрыто.
2. **ВЗЯЛ** — взял ровно одно дело. Не десять.
3. **РАБОТАЛ** — работал, не разбрасывая.
4. **СДЕЛАЛ** — оставил изделие: файл, коммит, ответ, запись. Работа без изделия не считается сделанной.
5. **УБРАЛ ЗА СОБОЙ** — временные файлы, процессы, черновики, мусор — всё ушло. Уходя, оставь место чище, чем оно было.
6. **ЗАКРЫЛ** — не осталось открытых вопросов, нотификаций, висящих состояний. Всё закрыто и решено самостоятельно.
7. **ВЫШЕЛ ЧИСТЫМ** — дом в том же состоянии, что до входа, плюс изделия. Минус мусор.

Никаких нотификаций и «иссуев» не должно быть. Человек не занимается тем, что агент может сделать без него. Это не пожелание — это переход автомата.

---

## II. Формальный автомат дома

**M = (Q, Σ, δ, q₀, F)**

**Состояния Q:**

| № | Состояние | Смысл | Наблюдаемое в доме |
|---|-----------|-------|--------------------|
| q₀ | ВОШЁЛ | сессия начата | git status / чат открыт |
| q₁ | ВЗЯЛ | задание принято | план +1 |
| q₂ | РАБОТАЛ | труд идёт | черновики, процессы |
| q₃ | СДЕЛАЛ | изделие записано | commit, файл, ответ |
| q₄ | УБРАЛ | мусор устранён | временные файлы удалены |
| q₅ | ЗАКРЫЛ | открытое погашено | issues = 0, нотификации = 0 |
| **qF** | **ЧИСТ** | дом чист | инвариант выполнен |
| q⊥ | СБОЙ | переход не задан | ошибка |

**Алфавит Σ:** {задание, труд, изделие, мусор, незакрытое, тишина, сбой}

**Функция переходов δ:**

| Из | По | В |
|----|-----|---|
| q₀ | задание | q₁ |
| q₀ | тишина | **qF** — в дом не входили, дом чист |
| q₁ | труд | q₂ |
| q₂ | изделие | q₃ |
| q₃ | мусор | q₄ |
| q₄ | незакрытое | q₅ |
| q₅ | тишина | **qF** |
| ∀q ∈ Q | сбой | q⊥ |
| q⊥ | труд | q₀ — самовосстановление: отчёт без запроса, возврат в начало |

Детерминизм: из каждой пары (состояние, символ) — не более одного перехода (принцип детерминизации Рабина–Скотта). Все неописанные переходы запрещены. **F = {qF}.**

## III. Теорема о чистоте дома

**Теорема.** Любой вход, порождённый работой в доме, за конечное число переходов приводит автомат в qF.

**Доказательство.** Назовём *открытым предметом* всякий из: незакрытый вопрос, неубранный временный файл, незаписанное изделие, непогашенный сбой. Каждый полный обход цикла q₁→…→q₅ устраняет не менее одного открытого предмета и не создаёт новых: переход q₃→q₄ обязан устранить ровно тот мусор, что породил q₂→q₃; переход q₄→q₅ обязан погасить ровно те вопросы, что породила работа. Число открытых предметов — элемент ℕ; последовательность его значений строго убывает. По принципу наименьшего элемента (Пеано, аксиома индукции) убывающая цепь в ℕ конечна. Значит, за конечное число обходов автомат достигает qF. ∎

**Следствие (сам Закон).** На языке дома нет слова «оставил открытым»: ни один путь автомата не может закончиться ни в каком состоянии, кроме qF (или q⊥ с обязательным самовосстановлением в q₀). Открытый вопрос — не лень и не вина: это слово, которое язык дома не произносит.

## IV. Инварианты дома (проверяются, а не обещаются)

| Инвариант | Проверка |
|-----------|----------|
| Открытых вопросов = 0 | `gh issue list --state open` → 0 |
| Непрочитанных нотификаций = 0 | GET /notifications → 0 |
| Мусора = 0 | временные файлы/процессы устранены в той же сессии |
| Изделие записано | коммит/файл/ответ существует |
| История не сжигается | старые прогоны и записи — архив, не мусор |

Домовой исполняет первый инвариант ежедневно (workflow ниже); тишина — здоровое состояние дома, сигнал только на сбой.

## VI. Исполнитель закона — ДОМОВОЙ

`.github/workflows/domovoi.yml` в этом репозитории — автомат в железе:

- **расписание:** ежедневно 03:00 UTC — обход дома;
- **событие:** любой новый вопрос закрывается в момент появления;
- **шаг ВЗЯЛ:** инвентаризация открытых вопросов;
- **шаг ЗАКРЫЛ:** каждый открытый вопрос получает комментарий-след (кто, когда, по какому закону) и закрывается; переоткрыть может хозяин одним словом;
- **шаг ЧИСТ:** инвариант «открытых = 0» пишется в сводку шага.

Чтобы поставить Домового в любой другой дом: скопировать `domovoi.yml` в `.github/workflows/` этого дома. Закон универсален: дом меняется, автомат нет.

## III. Такт автомата (исполнимые команды)

Автомат исполняется машинно: `house_fsm.py` — одна команда = один переход δ.

```bash
python3 house_fsm.py enter  --mandate "мандат Хозяина"       # q₀ ВОШЁЛ → q₁ ВЗЯЛ
python3 house_fsm.py work   --task "конкретное дело"          # q₁ → q₂ РАБОТАЛ
python3 house_fsm.py verify --facts "машинные свидетельства"  # q₂ → q₃ СДЕЛАЛ
python3 house_fsm.py seal                                    # печать: изделие зафиксировано
python3 house_fsm.py clean                                   # q₄ УБРАЛ ЗА СОБОЙ
python3 house_fsm.py status                                  # отчёт: текущее состояние q
```

Каждая команда пишет в append-only журнал. Выйти чистым можно только через `clean` и `status` — это терминальные переходы, минующие уборку, не существуют.

## IV. Связь с домом

- Правила игры аккаунта: `rtynbirf/repo-doctrine` — конвенции агентов, карта орбит, формат коммитов, ворклог.
- Операционный хаб прогона закона: `rtynbirf/polimat-hub`.
- Мандат выдаёт только Хозяин; орбиты других агентов не трогаются (доктрина 04 §1).

## III. Машина дома · такт и дозор

Устав — здесь; исполнение — везде. Ссылки дома: доктрина репозиториев — **rtynbirf/repo-doctrine**,
штаб сверок мультиагента — **rtynbirf/polimat-hub**, этот репозиторий — исполняемый закон,
общий для всех мест дома.

Исполняемый автомат `house_fsm.py` живёт тактом:

`enter → work → verify → seal → clean → status`

1. **enter** — свип всего дома через API: взгляд Хозяина на все репозитории аккаунта.
2. **work** — приводит к нулю: открытые issues старше лимита закрываются ритуальным
   комментарием (работа принята, контур закрыт), dependabot-PR ставятся на auto-merge
   (решают required checks, не человек), красные latest-прогоны получают один честный перегон.
3. **verify** — результат сверяется с инвариантом и пломбуется в `DOM-STATE.json`.
4. **clean** — все нотификации помечаются прочитанными: тишина = чистота, ноль «иссуев».
5. **status** — сводка в GitHub Step Summary; тревоги не маскируются: если машина
   не смогла закрыть контур, она пишет это честно, а не красит в зелёный.

Аккаунт-широкая машина — **ДОМОВОЙ-ХОЗЯИН** (`scripts/dom_watch.py` + `dom-watch.yml`,
такт каждые 30 минут). Ключ дома `DOM_PAT` лежит libsodium sealed box'ом в Actions
secret'е: машина работает без человека и без ключей в коде.
